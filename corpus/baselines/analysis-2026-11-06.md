# N1 and PL/Scope baseline, 6 November 2026

The before/after JSON files in this directory contain per-repository metrics,
diagnostic groups, and source locations. Each repository was indexed in its own
catalog. Both runs processed 138,451 compilation units, and every cold and warm
index was byte-identical. Degraded units fell from 10,450 to 1,643.

The largest group in the original data was 8,928 parse errors near a comma in
`db-sample-schemas/order_entry/oe_p_ar.sql` and related data scripts. These are
SQL*Plus continuations with trailing hyphens. After supporting continuations
outside literals, that repository fell from 8,969 to 329 degraded units. Some
remaining data files use continuations inside multiline string literals, where
preserving line positions requires further work. Substitution delimiters such
as `&&owner..object` account for another group, including 69 parse errors in
utPLSQL before the fix; its degraded units fell from 184 to 115.

The remaining oracle-db-examples diagnostics include 684 parser errors near
`USING`, often Oracle data-mining `PREDICTION(... USING ...)`. Diagnostic groups
such as dynamic SQL and ambiguous overloads are separate from degraded-unit
counts; they can arise even when parsing succeeded. Results depend on the
default schema and conditional compilation flags, and are not precision scores.

The warm CPU profile for oracle-db-examples (`n1-warm-cpu-local-2026-11-06.txt`)
recorded 7.34 seconds of sampled CPU over 6.24 seconds elapsed. Cache-key
computation accounted for 4.41 seconds cumulative sampled CPU; this includes
catalog fingerprinting and identifier matching. Profiles are machine- and
workload-specific, and cumulative times include callees.

For the N2 smoke test, Oracle Free compiled the pinned utPLSQL demo `BETWNSTR`
function with `PLSCOPE_SETTINGS='IDENTIFIERS:ALL, STATEMENTS:ALL'`. The report
contains 20 compiler rows: 14 have an in-source declaration that maps to a SCIP
symbol and match that symbol at the reported source position; six are
unanchored built-ins. One declaration and assignment share a position, so these
are rows, not distinct source ranges. This checks consistency on one function;
it does not validate access roles or prove that the declaration's target itself
is correct, and it is not the corpus-wide accuracy target.

## Follow-up

Treating `REM` lines as SQL*Plus comments before scanning literals eliminated
288 further errors in `db-sample-schemas`. A conservative parser surrogate for
mining calls with `USING *` or simple column lists reduced the oracle-db-examples degraded
count from 1,171 to 694. The surrogate does not resolve mining model names;
those uses receive `mining-model-unresolved` diagnostics. N1 fell from 1,643
to 878 degraded units overall. The detailed per-repository results are in
`n1-per-repo-optimized-2026-11-06.json`.

Precomputed catalog fingerprints replace a full catalog scan for each file.
The synthetic N3 result in `n3-optimized-local-2026-11-06.json` measures cold,
warm, and one-file-change runs. It is a simple generated workload, not a real
PR or a broad performance guarantee.

The expanded PL/Scope fixture adds `AWARD_BONUS` and `REMOVE_ROOMS_BY_NAME` to
`BETWNSTR`. It exposed a missing local exception reference, which was fixed.
Across the three objects, 32 compiler rows match their locally anchored SCIP
symbols and 22 are unanchored; the report still does not evaluate external
targets or access roles. See `plscope-expanded-local-2026-11-06.json`.

## N2 package scenario and mining follow-up

The N2 fixture adds package spec/body, overloads, nested scopes, calls from a
second object, SQL column reads and writes, and a table supplied only by the
catalog. It records PL/Scope signatures across all three documents, uses
explicit expected symbols for the package/overloads and table/columns, and
compares two SQL column roles against annotated fixture expectations. Oracle
reports both column uses as `REFERENCE`; those two roles are not inferred from
PL/Scope. The local result in `n2-fixture-local-2026-11-06.json` has 56 matched
rows, 18 unanchored rows and 49 matched role checks. This is a controlled
fixture, not a corpus-wide accuracy measurement.

Additional mining surrogates cover simple literal/column features with `AS`,
`COST MODEL` and `OF ANOMALY`. They retain a warning because mining models are
not resolved. N1 degraded units fell from 878 to 781; all ten cold and warm
indexes matched. The grouped diagnostics and representative source locations
are in `n1-per-repo-n2-2026-11-06.json`. Remaining errors include unsupported
mining expressions and scripts whose SQL*Plus substitution values are unknown;
neither category should be silently classified as resolved.

## Types, two schemas and remaining N1 cases

The N2 fixture now includes a synonym and a package in `N2_EXT`, a local object
type, `%TYPE` and `%ROWTYPE`, and a row trigger. `N2_REMOTE` is exported as
SYSTEM so both package specification and body are visible. The comparator
distinguishes extra overload candidates from exact matches. In the local run,
83 PL/Scope rows match, two calls remain ambiguous, and 22 rows are unanchored;
77 roles match. Five additional fixture expectations check two trigger roles
and three type-definition relationships, none of which are inferred from the
PL/Scope rows. See `n2-types-cross-schema-local-2026-11-06.json`.

Qualified wildcards, simple qualified arguments and `CLUSTER_DISTANCE` in
mining expressions lower the N1 degraded-unit count from 781 to 704; the ten cold and warm outputs remain
byte-identical. Both measurements were repeated with the current dependencies;
the control is `n1-per-repo-before-types-2026-11-06.json`. Unknown SQL*Plus substitutions now have an explicit diagnostic;
1,234 such occurrences were observed across N1. Their values are not currently
configurable: arbitrary-length substitutions require a source-offset map and
careful handling of SQL*Plus context. Results are in
`n1-per-repo-types-2026-11-06.json`.
